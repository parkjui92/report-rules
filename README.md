# report-rules

**한국어 보고서를 쓰기 전에 읽히는 규칙, 쓰고 나서 돌리는 점검기.**

정책연구보고서·기획보고서, 요약본·정책브리프·추진계획(안)·보고자료, 자문의견서·검토의견서를 쓰는 사람을 위한 도구입니다. Claude Code 스킬로 설치하면 Claude가 보고서를 쓸 때 이 규칙을 먼저 읽고, 다 쓴 초안을 규칙대로 점검해 줍니다. 파이썬 점검기만 따로 써도 됩니다.

> AI가 쓴 보고서 초안은 대개 문법은 맞는데 어딘가 어색합니다. "~로 사료됨"이 끝없이 나오고, 문장마다 긴 대시(—) 뒤에 해설이 붙고, 「」가 아무 개념에나 씌워집니다. 이 저장소는 한 연구자가 AI 초안을 직접 고친 흔적에서 그 "어딘가"를 규칙으로 뽑아낸 것입니다.

## 이런 분께 맞습니다

- 정부·공공기관에 **정책연구보고서, 추진계획(안), 자문의견서**를 내는 연구자·실무자
- AI로 초안을 쓰는데 **"AI가 쓴 티"와 공문서 문체 사이**에서 매번 손으로 고치는 분
- 팀에서 보고서 문체를 **하나의 기준**으로 맞추고 싶은 분
- 자기만의 문체 규칙을 **근거와 함께** 만들어 두고 싶은 분

학술논문·슬라이드·정부 R&D 제안서는 따로 규칙이 있어야 하는 장르라 이 저장소의 범위가 아닙니다.

## 3분 만에 써 보기

설치 없이 점검기부터 돌려 볼 수 있습니다. 파이썬 3.9 이상이면 되고, 추가 패키지는 필요 없습니다.

```bash
git clone https://github.com/parkjui92/report-rules.git
cd report-rules
python3 scripts/rcheck.py check examples/sample_draft.md --type brief
```

`examples/sample_draft.md`는 흔한 실수를 일부러 넣은 짧은 추진계획(안)입니다. 이런 리포트가 나옵니다.

```
유형: `brief` · rcheck 1.0.0 · [필수] 4 / [권고] 6 / [참고] 3

### [필수] 판단 유보어
- L3: …규제 개선이 시급한 것으로 사료됨

### [필수] 괄호 안 장·절 상호참조
- L5: ○ 해외 주요국은 다양한 제도를 도입함(제2장 제1절에서 상술함)

### [필수] 작업 흔적
- L9: …example.go.kr/report?utm_source=chatgpt.com

### [권고] 지시형 '~할 것'·'~바람'
- L7: …관계 부처는 2026-10-01까지 개선안을 제출할 것
```

각 지적 아래에는 **왜 문제인지, 어떻게 고치는지**가 한 줄씩 붙습니다. 이제 자기 초안에 돌려 보세요.

```bash
python3 scripts/rcheck.py check 내초안.hwpx --type research
```

| 권 | 이럴 때 | 예를 들면 |
|---|---|---|
| ① 공통 | 언제나 먼저 | 검증된 것만 쓴다, 판단은 단언한다, 「」는 법령·문서명에만 |
| ② 연구보고서 | 50쪽 안팎의 납품 보고서 | 목차만 읽어도 문제→원인→대안→제언이 보이게, 제언엔 주체·시점·재원·법 개정 여부 |

| ④ 자문의견서 | 남의 원고·법안에 의견 주기 | 요청받은 범위만, 항목마다 진단·근거·제언, 판단은 단언하되 요구는 제안형으로 |

## Claude Code에서 쓰기

### 설치

```bash
git clone https://github.com/parkjui92/report-rules.git ~/.claude/skills/report-rules
```

이것으로 끝입니다. 다음 Claude Code 세션부터 스킬이 보입니다.

### 이렇게 말하면 됩니다

| 하고 싶은 것 | 말 예시 | 스킬이 하는 일 |
|---|---|---|
| 새로 쓰기 | "이 법안에 대한 검토의견서 써줘" | 공통 + 자문의견서 규칙을 먼저 읽고 씀 |
| 점검 | "이 초안 규칙 점검해줘" | 점검기 실행 + 점검표 판정 → `초안_규칙점검.md` 리포트 |
| 점검 후 수정 | "점검 결과대로 고쳐줘" | 고친 뒤 점검기를 다시 돌려 [필수]가 줄었는지 확인 |
| 규칙 추가 | "앞으로 '제고'는 '높임'으로 써" | 해당 규칙 파일과 점검기에 근거와 함께 추가 |

점검 리포트는 이런 모양입니다.

1. **한 줄 판정** — 넘겨도 됨 / 고친 뒤 넘김 / 다시 씀
2. **점검표 요약** — 스크립트가 못 보는 것(논증이 비었나, 제언에 주체가 있나)
3. **수정 요청 표** — `위치 | 문제 | 수정안 | 등급 | 규칙`. 수정안은 "이렇게 바꾸세요"라는 **완성된 문장**으로 줍니다
4. **점검기 리포트**(부록)

## 점검기 자세히

### 명령 세 가지

```bash
# 1) 점검 — 문서 유형을 골라 주세요
python3 scripts/rcheck.py check 초안.hwpx --type research     # 연구보고서
python3 scripts/rcheck.py check 계획.md   --type brief        # 브리프·추진계획(안)
python3 scripts/rcheck.py check 의견.docx --type advisory     # 자문의견서
python3 scripts/rcheck.py check 문서.md   --type common       # 잘 모르겠으면

# 결과를 파일로 저장하려면 -o, 다른 도구에 넘기려면 --json
python3 scripts/rcheck.py check 초안.hwpx --type research -o 점검결과.md

# 2) 비교 — 초안과 최종본의 문체가 얼마나 달라졌나
python3 scripts/rcheck.py stats 초안.hwpx 최종본.hwpx

# 3) 자체검사
python3 scripts/rcheck.py selftest
```

`.hwp`는 한글에서 `.hwpx`로 다른 이름으로 저장한 뒤 넣어 주세요.

### 무엇을 보나

| 등급 | 뜻 | 항목 |
|---|---|---|
| **[필수]** | 내보내기 전에 꼭 고침 | 판단 유보어(`사료됨`·`것으로 보인다`) · 괄호 안 장·절 상호참조 · 작업 흔적(`utm_source`, 편집 메모, 미검증 표지) · 긴 대시 과다 |
| **[권고]** | 고치는 게 기본 | "이는 ~를 반영함" 해설 꼬리 · 대시로 이은 두 문장 · 번역투 · 상투어 · 날짜 표기 · 띄어쓰기 · 지시형 `~할 것` · 개조식 문서의 `~다.` · ▲·『』 · 볼드 남발 |
| **[참고]** | 문맥 보고 판단 | 「」 오용 · 개수 수사 · 대비 구문 과다 · 빈 수식어 · 최상급 · 따옴표 혼용 · 줄 길이 |

### 알아 두실 것

- **오탐이 있습니다.** 특히 「」(문서 제목인데 개념으로 오인), 띄어쓰기, 최상급이 그렇습니다. 리포트는 "여기를 한 번 보세요"라는 뜻이지 "틀렸다"는 판정이 아닙니다.
- **내용은 보지 않습니다.** 논증이 탄탄한지, 근거가 주장을 감당하는지, 제언이 실행 가능한지는 점검기가 판단할 수 없습니다. 그건 규칙 파일 끝의 점검표로 사람(또는 Claude)이 봅니다.
- **실제로 가르는지 확인했습니다.** 저자의 실제 문서에 돌렸을 때 AI 초안과 저자 최종본이 이렇게 갈렸습니다.

  | 문서 | AI 초안 | 저자 최종본 |
  |---|---|---|
  | 정책연구보고서 | [필수] 84건 | [필수] 20건 |
  | 검토의견서 | [필수] 6 · [권고] 26건 | [필수] 0 · [권고] 8건 |

## 규칙 맛보기

전체는 `references/`에 있습니다. 실측에서 나온 몇 가지만 소개합니다.

**판단은 단언하고, 상대에게 요구하는 문장만 부드럽게.**
저자는 의견서를 고칠 때 AI가 쓴 `~할 것`을 `~하면 좋을 것으로 판단함`으로 바꿨습니다. 그런데 보고서의 판단 문장에서는 `사료됨`을 한 번도 쓰지 않았습니다. 누그러뜨리는 건 예의의 문제이지 확신의 문제가 아니라는 뜻입니다.

| AI 초안 | 저자 최종본 |
|---|---|
| …과제로 추가할 것 | …과제로 추가하면 좋을 것으로 판단함 |
| …두는 것만으로는 부족함 | …두는 것만으로는 부족할 수 있음 |

**긴 대시 뒤에 해설을 붙이지 않는다.**
AI 초안을 가르는 가장 뚜렷한 표지였습니다. 저자 최종본은 1만 자당 0.9~5.1회, AI 초안은 11.5~50회. 한 보고서에서 저자는 208개를 57개로 줄였습니다.

**"이는 ~를 반영함" 꼬리를 지운다.**

| 전 | 후 |
|---|---|
| …4단 연계 구조를 채택하고 있으며, 이는 AI 정책이 다층적 통합 설계로 작동해야 한다는 글로벌 인식을 반영함 | …4단 연계 구조를 채택하고 있음 |

**「」는 법령·문서명에만, 개념은 ' '.** **추정 수치는 합산식과 각 항의 출처를 한 줄로.** **회의록·RFP·메일 같은 내부 자료는 출처가 아니다.** **계획서는 아직 안 한 일의 계획이라 "지정·확정·완성"으로 쓰지 않는다.**

## 이 규칙은 어디서 왔나

원칙을 나열한 작성 요령은 이미 많습니다. 이 규칙이 다른 점은 **근거가 붙어 있다**는 것입니다. 네 갈래에서 모아 하나로 합쳤습니다.

| 갈래 | 무엇을 봤나 | 규모 |
|---|---|---|
| 저자 최종본 | AI 초안과 저자가 직접 마무리한 최종본을 쌍으로 대조 | 약 45건 |
| 저자 피드백 | AI 작업 세션에서 저자가 한 지적·승인 | 856건 정독 |
| 기존 규칙 | 양식 규격·교정 규칙 등을 통합하고 서로 어긋나는 곳 판정 | 18종, 충돌 23건 |
| 외부 표준 | 아래 원문을 쪽수까지 대조 | [docs/sources.md](docs/sources.md) |

외부 표준으로는 「행정업무의 운영 및 혁신에 관한 규정」과 시행규칙(법제처), 행정안전부 「행정업무운영 편람」·「정책연구관리 업무편람」, 국립국어원 『쉬운 공문서 쓰기 길잡이』, RAND 연구 품질 기준, 하버드 케네디스쿨 정책 메모 가이드, IDRC·ODI 정책브리프 가이드 등을 원문으로 확인했습니다. 2차 자료만 보고 넣었던 두 항목이 원문과 달라 고친 기록도 남겨 두었습니다.

근거가 부딪히면 **저자 최종본 > 반복된 피드백 > 기존 규칙 > 외부 표준** 순으로 정했습니다. 규칙 문서 안의 "저자"는 이 규칙을 만든 원 저자를 뜻하고, "문서 A·B·C"는 익명화한 실제 문서입니다.

## 내 규칙 만들기

이 규칙은 한 사람의 문체입니다. 그대로 써도 되지만, **자기 문서에서 다시 뽑으면 훨씬 잘 맞습니다.** 만든 방법을 그대로 공개했습니다 → [docs/build-your-own.md](docs/build-your-own.md)

첫걸음은 두 명령입니다.

```bash
# 내가 Claude Code 세션에서 한 지적을 프로젝트별로 모으기
python3 scripts/mine_feedback.py -o feedback.md

# 내가 초안을 어느 방향으로 고쳤는지 재기
python3 scripts/rcheck.py stats 초안.hwpx 최종본.hwpx
```

`feedback.md`에는 대화 원문이 들어 있으니 공유하지 마세요(`.gitignore`에 넣어 두었습니다).

## 자주 묻는 것

**Claude Code 없이도 쓸 수 있나요?**
네. `scripts/rcheck.py`는 파이썬 표준 라이브러리만 쓰는 독립 스크립트입니다. 규칙 문서는 그냥 읽어도 되고, 다른 AI 도구에 붙여 넣어도 됩니다.

**우리 기관 양식과 규칙이 다르면요?**
양식이 이깁니다. 우선순위는 `사용자의 개별 지시 > 발주처 양식·샘플 문서 > 유형별 규칙 > 공통 규칙`입니다.

**개조식이 일본어 투라는 말도 있던데요?**
국립국어원도 명사형 종결(`~함`·`~임`)의 유래를 특정하지 못한다고 답했습니다. 금지할 공식 근거는 없습니다. 이 규칙은 개조식 문서에서는 쓰고 서술형 본문에서는 쓰지 않는 쪽입니다.

**점검기가 제 문서를 너무 많이 잡아요.**
규칙이 내 문체와 안 맞는 것일 수 있습니다. 내가 만족한 최종본 몇 건에 돌려 보고, 거기서도 잔뜩 걸리는 항목은 `scripts/rcheck.py`의 `WORD_RULES`에서 등급을 낮추거나 빼세요. 이 저장소도 그렇게 조정했습니다("내 최종본이 걸리면 규칙이 틀린 것").

**규칙을 고치거나 더하고 싶어요.**
`references/`의 규칙 파일을 고치고, 기계로 셀 수 있는 규칙이면 `rcheck.py`의 `WORD_RULES`에 정규식을, `SELFTEST`(걸려야 할 예문)와 `NEGATIVE`(걸리면 안 되는 예문)에 한 줄씩 더한 뒤 `python3 scripts/rcheck.py selftest`로 확인하세요. 이슈·PR 환영합니다.
