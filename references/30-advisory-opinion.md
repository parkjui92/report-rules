# 보고서 작성 규칙 ④ 자문의견서

> **선독 순서**: `00-common.md`(공통)를 먼저 읽고 이 파일을 읽는다. 공통 규칙과 겹치면 이 파일이 이긴다.
> **적용 대상**: 자문의견서 · 검토의견서 · 법안·조문 검토의견 · 명칭·제도 의견 · 전문가 자문회의 의견 · 논문·과제 심사의견
> ※ 결론-이유-대안 구조를 공식 규정한 **한국 지침은 없다**(외부 조사 결과). 이 파일의 구조는 저자 최종본 관측 + 국내 검토보고서 실물 + 해외 정책·결정 메모 가이드의 조합이다.
> **근거**: 검토의견서 B 5단 개정 체인(AI 원고 → 저자 최종 hwpx) · 제도 의견서 J(md 원고 → 최종 비교표) · 자문의견서 K(2025년 작성, **AI 도움 이전 저자 문체 기준점**) · 자문의견서 I 2종 · 조문 검토의견 L(저자 승인: "오케이 잘했다") · 논문 심사의견 작업 발화 · 작업 세션 피드백 채굴(자문 관련 12개 규칙)

자문의견서는 **다른 사람의 원고·계획·법안에 대해 전문가로서 판단을 주는 글**이다. 보고서와 가장 크게 다른 점은 두 가지다.
1. **판단은 단언하되, 상대에게 요구하는 문장은 제안형으로 쓴다**(§3). 저자가 AI 원고를 고칠 때 가장 일관되게 한 일이다.
2. **요청받은 범위 안에서, 논리 수준의 코멘트만** 준다(§1). 교정교열 수준의 지적은 넣지 않는다.

## 1. 범위와 형태 — 쓰기 전에 정한다

### 1.1 요청받은 범위만 쓴다
- 자문 요청서·회의 안건이 준 **질문(축)을 그대로 장 구조로 받는다**. 요청이 "실효성·기존 제도 연계·영향평가 연계" 세 축이면 의견서도 그 세 축으로 짠다
- 연구진이 할 몫(분석 수행·결과 작성)은 쓰지 않는다 — "나는 그냥 전문가로서 위의 내용만 요청받은 건데"(저자 피드백)
- 요청 밖이지만 꼭 필요한 지적은 말미 `□ 기타 의견` 한 곳에만 모은다

### 1.2 형태 선택

| 상황 | 형태 | 근거 |
|---|---|---|
| **검토 대상 원문(hwpx·양식)이 있다** | **원문 양식 위에 파란색 검토의견을 단다**(기본값). 별도 표로 떼어 내지 않는다 | "표로 말고 원래 양식에 파란색 검토의견을 다는 게 어때"(저자 피드백) — 표 방식에서 뒤집힘 |
| 원문 없이 종합 의견을 요청받았다 | 별도 의견서 3부 구성(§2) | 검토의견서 B 최종본 |
| 명칭·선택지 중에서 골라 달라는 요청 | 후보 비교표 1장(§5.2) | 제도 의견서 J — 서술형 원고 5개 절을 표 1장으로 전면 교체 |
| 안건이 여러 개인 자문회의 | 안건형(`안건 n.` → `□` 헤드라인 → `○ 라벨: 설명` → 판단 기준표) | 자문의견서 I |
| 조문(법안) 검토 | 기존 조문을 찾아 대조하고, **꼭 고쳐야 할 것만** 원문에 파란색으로 직접 수정 | 조문 검토의견 L(저자 승인) |
| 논문·과제 심사 | §6 심사의견 특칙 | 논문 심사 작업 |

### 1.3 분량
- 기본 **1~3쪽**. 명칭 의견처럼 결론이 하나인 것은 **1쪽·표 하나**로 압축("hwp 1p 정도로", "하나의 표로 합쳐")
- 분량을 늘릴 때는 항목을 늘리지 말고 **근거를 깊게** 한다 — "더 나은 의견서를 작성해, 2~3p까지도 괜찮아"

## 2. 별도 의견서의 골격

```
「검토 대상 제목」 검토의견서
(2026. 9. 23.(수), 작성자)

Ⅰ. 총괄 의견
  □ 종합 표 — 자문 요청사항 | 판단 | 보완 및 제안사항
  □ 연구(계획)의 기여
  □ 핵심 한계와 보완 방향
Ⅱ. 장별(항목별) 검토의견
  □ 제n장 「장 제목」
    ○ (문제 라벨) 진단 …있어 / …하므로 처방
      - 근거(조문·통계·선례)
Ⅲ. 자문 사항별 의견        ← 요청서의 질문을 그대로 소제목으로
```

- **머리는 제목 + 날짜·작성자 한 줄**이다. `검토 대상 · 검토 범위 · 검토자 · 검토일` 메타 표는 두지 않는다(AI 원고에 있던 것을 저자가 삭제)
- **Ⅰ 첫머리는 3열 표**(자문 요청사항 | 판단 | 보완 및 제안사항). 표만 읽어도 결론이 서야 한다
- **기여를 한계보다 먼저** 쓴다. 상대 연구진이 읽는 글이다
- **쟁점 단위로 나누고 쟁점마다 판단을 낸다.** 지방의회 전문위원 검토보고서 실물(서울시의회, 2025.11)도 `Ⅰ.제출경과 → Ⅱ.제안이유 → Ⅲ.주요내용 → Ⅳ.참고사항(관계법령) → Ⅴ.검토의견` 뒤 검토의견을 번호 붙인 쟁점으로 나누고, 쟁점마다 근거 조문·수치를 달아 "적합할 것으로 판단됨"으로 닫는다
- 선택을 요청받았다면 결정 메모 구조를 빌린다: 목적 → 배경·맥락 → **대안과 각 대안의 함의** → 시한 → **구체적 행동을 담은 명확한 권고**(미 국토안보부 결정 메모 서식 원문: "present options for resolution and explain the implications", "a clear recommendation of specific action(s)")
- 2025년 저자 문체(AI 이전)의 문단 흐름도 유효하다: `[1] 질문` → 원인 `(라벨)` 나열 → `따라서, ①…②…③…` 종합 → 처방 `(라벨)` 나열 → `다만, …` 균형 단서로 닫기

## 3. 어조 — 판단은 단언, 요구는 제안형

저자가 AI 원고를 최종본으로 고치며 **가장 일관되게 바꾼 것**이다(검토의견서 B의 AI 원고→저자 최종본, 자문의견서 I의 AI 원고→저자 최종본).

### 3.1 경계
| 문장의 기능 | 어조 | 예 |
|---|---|---|
| **사실·판단**(무엇이 맞고 틀린가) | 단언. 판단 유보어 금지(공통 §2.1) | "현행 「○○법」 제12조와 어긋남", "인과가 성립하지 않음" |
| **상대에게 요구·권고**(무엇을 하라) | **제안형** | 아래 표 |

판단까지 흐리면 공통 규칙(판단 유보 금지)을 어긴다. **누그러뜨리는 것은 요구 문장뿐이다.** 연구보고서 본문에서 저자는 "~로 보임"·"사료됨"을 0회 썼다.

### 3.2 요구 문장 바꿔 쓰기
| AI 원고(지시형·단정형) | 저자 최종(제안형) |
|---|---|
| …전면에 배치할 것 | …전면에 배치하면 좋을 듯함 |
| …과제로 추가할 것 | …과제로 추가하면 좋을 것으로 판단함 |
| …두는 것만으로는 부족함 | …두는 것만으로는 부족할 수 있음 |
| …세 조건이 좌우함 | …세 조건이 좌우할 수 있어 다음 내용을 고려할 필요가 있음 |
| 가장 큰 보완이 필요한 영역 / 실행 설계는 미흡 | 핵심적으로 보완이 필요한 영역 / 실행 설계 보완 필요 |

- 쓸 어미: `~할 필요가 있음` · `~하면 좋을 것으로 판단함` · `~을 검토할 필요가 있겠음` · `~보완 필요`
- 지시형 `~할 것`은 **서식·기재 요구처럼 이견이 없는 사항**에만 남긴다. 공문서 규범도 `~할 것`·`~바람`을 고압적 표현으로 분류한다(행정업무운영 편람 p.55·76, 국립국어원 길잡이 p.22~23)
- "미흡·부족·잘못" 같은 평가어는 "보완 필요"로 바꾸고, 무엇을 보완할지를 바로 붙인다

## 4. 항목 하나의 구성 — 진단 · 근거 · 제언

### 4.1 기본 단위
- 한 항목 = **① 진단(무엇이 문제) ② 근거(왜 그렇게 판단) ③ 제언(무엇을 어떻게 바꾸라)**. 필요하면 **④ 수정 문안 예시**
- 제언은 **"현재 → 제안 → 이유"** 가 보이게 쓴다 — "뭘 어떻게 바꾸라는 건지가 명확하면 좋겠어"(저자 피드백)
- "보강 필요"로 비워 두지 말고 **직접 제안한다** — "보강 필요라고 하지 말고 제안해"

### 4.2 한 줄로 합친다
AI 원고는 `- 문제` + `  - 처방` 2단이었는데, 저자 최종본은 **`○ (라벨) 문제 …있어 / …하며 / …하므로 처방` 한 줄**로 합쳤다.
- A: `(필요성의 분리) …한 논거에 섞여 있음` / `  - 결과기반 전환은 … 두 논거를 분리해야 인과가 선명해짐`
- B: `(필요성의 분리) …한 논거에 섞여 있어 수정보완이 필요하며, 결과기반 전환은 … 분리해야 인과가 선명`
- 근거(조문·통계·선례)만 `-` 하위 줄로 내린다
- ※ 기획 브리프는 반대로 헤드라인을 쪼갠다(`20-brief.md`). 의견서=합치기, 브리프=헤드라인 분리

### 4.3 무엇을 지적하나
- **논리 수준의 코멘트만** — 인과·필요성 논거·제도 정합·실행 가능성·근거의 크기. "마이너한 수정은 불필요"(저자 피드백)
- 오탈자·띄어쓰기·표현 다듬기는 넣지 않는다. 꼭 필요하면 원문에 파란색으로 직접 고치고 의견 항목으로 세지 않는다
- **꼭 바꿔야 할 것을 앞에** 둔다. 항목이 많으면 "꼭 바꿔야 할 것"과 "고려 사항"을 나눈다

## 5. 근거와 관점

### 5.1 근거
- **법령**: `「법률명」 제n조 제n항 제n호` 풀네임, 시행일 병기 `(2026. 8. 28. 시행)`. 조문 문언은 큰따옴표 직접인용. **법제처 원문으로 조문 단위 대조**한 뒤에만 쓴다
- **해외 근거를 명칭·개념에 과대 귀속하지 않는다** — "EU에서 전문연구인력 명칭을 쓴 건 아니잖아". 해외가 그 제도를 운영한다고 그 용어를 쓴 것은 아니다
- 선례는 **한국 선례부터** 확인한다(있었다면 왜 안 됐는지)
- 확인이 안 된 곳은 지우지 말고 파란색으로 남긴다(공통 §1.6). 배포본에서는 확인 후 걷어 낸다

### 5.2 비교형 의견(명칭·선택지)
- 틀: **명칭 – 정의 – 기존 용어 충돌·제도 정합 – 주요 근거 – 입법 추진 리스크**(제도 의견서 J에서 저자가 지정)
- 후보 × 위 항목의 **비교표 1장** + `(권고 1순위)` · `(비권고)` 태그
- 너무 넓은 말("연구원")·병기안("연구원·기술원")은 적합성을 따져 걸러 낸다

### 5.3 전문가로서의 관점
- 자문의견은 **결론이 그대로 채택될 수 있는 문서**로 쓴다. 국회 상임위 전문위원 검토보고서의 수정 권고가 강할수록 정부 제출 법안이 원안대로 통과되는 비율이 낮았다(김형섭·홍준형, 『한국정책학회보』, 2018) — 검토의견은 실제로 결과를 바꾼다
- 독자를 먼저 본다: 무엇을 알고, 무엇을 정말 풀고 싶어 하며, 어떤 제약(법·예산·정치)이 있고, **그 사람이 풀 수 있는 문제인가**(HKS)
- "어떻게 할까요"가 아니라 **안을 들고 간다**(건의형)
- **이 청중 앞에서 우리가 보탤 관점**을 찾는다. 법률가 위원회에서는 법보다 정책·기술 층위를 강조한다(저자 피드백)
- 다른 위원들이 놓친 층위를 보강한다. 모두가 같은 곳(예: 윤리교육·취약계층)에 몰려 있으면 다른 접근을 제시한다
- 전제·가정·검증 범위를 서두 한 문단에 밝히고, 미확인 항목은 말미에 따로 모은다(저자가 좋다고 한 방식)

## 6. 논문·과제 심사의견 특칙

- 수치·표기 지적보다 **논쟁의 여지가 있는 쟁점**을 지적한다
- **"진짜 꼭 바꿔야 할 것" 3개 안팎**으로 압축한다
- 문장은 명료·정확하게. 심사위원용 의견과 저자 공개 의견을 **각 1문단**으로
- 판정(게재 가·수정 후 재심 등)과 지적의 무게가 맞아야 한다

## 7. 문체·서식

| 항목 | 규칙 | 근거 |
|---|---|---|
| 종결 | `~음·~함·~임` 개조식. `~다` 원고는 최종본에서 전환 | 자문의견서 K(AI 이전 기준점) 78%, 검토의견서 B 최종 55%, 제도 의견서 J 원고 ~다 40% → 최종 0% |
| 위계 | `Ⅰ.` → `□` → `○(라벨)` → `-`. `○` 줄이 길어져도 한 줄로 합치는 쪽이 우선(§4.2) | 검토의견서 B 최종본 |
| 라벨 | `(라벨)` 시작 줄 15~37%. 안건형은 `○ 라벨: 설명` 콜론 라벨 | 저자 최종본 3건 |
| 긴 대시 | 거의 쓰지 않는다(최종본 0.9/만자) | 검토의견서 B 최종본 |
| 강조 | 볼드 쓰지 않는다. 라벨이 강조를 대신한다 | 저자 최종본 2건 |
| 편집 표지 | 미검증 표시(`⟪…⟫`)·"파란색 표기는 확인이 필요함" 안내문은 확인 후 삭제 | 검토의견서 B의 AI 원고→저자 최종본 |

## 8. 배포 전 점검

기계 점검 항목은 `scripts/rcheck.py check <파일> --type advisory`로 먼저 돌린다.

- [ ] 요청서의 질문(축)이 전부 소제목으로 있고, 요청 밖 내용이 본문에 섞이지 않았다
- [ ] 총괄 표만 읽어도 판단이 선다
- [ ] 모든 항목에 진단·근거·제언이 있다. "보강 필요"로 비워 둔 곳이 없다
- [ ] 판단 문장에 유보어가 없고, 요구 문장에 지시형 `~할 것`이 남지 않았다
- [ ] 마이너 교정 지적이 의견 항목에 섞이지 않았다
- [ ] 법령은 법제처 원문과 조·항·호·시행일까지 대조했다
- [ ] 해외 사례를 명칭·개념으로 과대 귀속한 곳이 없다
- [ ] 메타 표·편집 표지·미검증 안내문이 남지 않았다
- [ ] 공통 규칙 `00-common.md` §9 점검표를 통과했다
