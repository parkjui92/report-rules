## 1. 사실과 근거

**가장 많이 반복된 규칙이다.** 기존 규칙 9개 파일에 같은 말이 있고, 저자는 "절대 할루시네이션 있으면 안 되니까" 류의 요구를 5개 세션에서 했다.

### 1.1 검증된 것만 쓴다
- 보고서에는 **확인된 사실만** 싣는다. 회의에서 나온 얘기는 관점만 반영하고 사실로 싣지 않는다 — "관점만 반영하지… 검증된 내용만 써"(저자 피드백)
- 근거 없는 수치는 쓰지 않는다. 없으면 찾아서 채우고, 못 찾으면 `〔확인 필요: 무엇〕`으로 비운다. **지어내지 않는다**
- 전달 직전에 원자료와 한 번 더 대조한다
- 공문서 원칙도 같다: "6하 원칙에 따라 작성하고 오·탈자나 계수 착오가 없도록", "애매모호하거나 과장된 표현에 의하여 사실이 왜곡되지" 않게(편람 p.75)

### 1.2 수치 규율
- **추정 수치는 합산식과 각 항의 출처를 한 줄로** 밝힌다: "A(출처) + B(출처) + C(출처) = 5.3조 원". 공식 통계가 있으면 **병기하고 공식 통계를 앞에** 둔다 — 한 세션에서 12회 요구(저자 피드백)
- 비중·비율은 **실제 결과값에서 산출**한다. 가정 비율 금지
- 통계 용어는 **원자료 용어 그대로**(집행 / 예산 / 정부안 / 확정을 구분) — "집행이면 집행으로 해야지"
- **원자료의 폭을 살린다**: "3년" → "3~4년", "정확도 80%" → "79.4%", "2021" → "2020~2021"
- **맞는 수치에 딸려 온 파생 수치**(환산액·균등분할액·인원 추정)가 가장 흔한 오류다. 한 문장의 수치 N개 = 검증 항목 N개
- 환산·비율은 전부 검산한다(10배 오류가 검수까지 살아남은 사례). 환산이 확인되지 않으면 지운다: "2천억 유로(한화 약 3조 원)" → "2천억 유로"
- 출처가 다른 재정 수치는 회계 기준이 같은지 확인하기 전에 합산하지 않는다
- 수치에는 기준연도·단위·정의를 붙인다: "89%(○○국, 2025년 기준)"
- **애매한 양 표현 금지**: 대체로·대부분·많은·어느 정도·상당한(『정책기획 실습』 p.83). 수치로 쓰거나 범위를 밝힌다

### 1.3 전망과 실측을 섞지 않는다
- 전망치·산술 추정치를 실측처럼 쓰지 않는다. 미달이면 미달이라고 쓴다 — "0.93은 다 빼고 0.81로 두고"(저자 피드백)
- "근접" → "미달", "즉시 활용 도구를 완성" → "확정안을 정비"(정책연구보고서 H 교정)

### 1.4 무엇이 출처인가
- **출처는 실제 발간된 보고서·논문·통계·법령·공식 발표**다
- **저자의 내부 작업자료는 출처가 아니다** — RFP·연구계획서·회의록·담당자 메일·검토의견서·저자가 준 메모. "내 폴더에 있는 자료로 인용한 것들… 삭제해"(저자 피드백 — 정책연구보고서 H에서 내부 인용 86건 제거). 요구사항은 서술문 성분으로, 관점은 공개 근거로 다시 받친다. 공개 근거를 못 찾으면 싣지 않는다
- **해외 근거를 과대 귀속하지 않는다**: 해외가 그 제도를 운영한다고 그 명칭·개념을 쓴 것은 아니다(의견서 J). 보도 원문이 말한 범위까지만 쓴다: "AI가 늘린 일자리" → "AI 관련 일자리 증가분"
- 내 주장을 세우지 말고 **"이런 선행연구가 있고 그것을 확장한다"** 로 근거를 세운다(저자 피드백)
- **2차 문헌에서 옮긴 인용은 재인용으로 표기**한다. 1차 문헌만 적는 것은 정책연구 윤리 점검기준의 '2차 문헌 표절'이다(정책연구관리 업무편람 p.32)
- 직접인용(큰따옴표)은 **원문에 문자 그대로 있을 때만**. 취지만 같으면 따옴표를 벗기고 의역한다
- 출처는 홈페이지가 아니라 **그 자료로 바로 가는 링크**로, 쪽수까지("27쪽" → "23·27~28쪽")
- 원자료는 내려받아 프로젝트 폴더에 보존한다

### 1.5 현행화
- 부처명·제도·계획 차수·법령 조항은 **작성 시점 기준**으로 확인한 것만: "예비타당성조사" → "사업기획점검", "산업통상자원부" → "산업통상부", "제5차" → "제6차 과학기술기본계획". **법령 인용문 안은 원문 유지**
- 시점 표현을 갱신한다: "시행을 앞두고" → "2026년 1월 22일부터 시행되어"
- 직함은 원문 그대로("CTO" → "최고기술펠로")

### 1.6 확인이 안 된 곳
- **지우지 말고 파란색으로 남겨 저자가 판단하게** 한다 — "확인 안 된 부분은 파란색으로 표기해줘"(4개 세션)
- 배포본에서는 확인 후 걷어 낸다. 검증 상태 태그(`〔검증〕`·`〔색인확인〕`)와 "읽는 법" 안내는 **최종 배포본에 남기지 않는다**

### 1.7 한 문서 안의 정합
- 수정은 **요약문·본문·표·부록까지 같은 용어·수치로 전파**한다(정책연구보고서 H 교정 22건: "사회적 영향" ↔ "사회적 가치" 불일치 등)
- "두 가지 문제"라고 쓰고 세 개를 나열하는 식의 개수 불일치, 존재하지 않는 절 참조를 없앤다
- **문제로 제기한 것은 대안·추진계획에서 반드시 다시 다룬다**. 추진전략이 두 개면 과제도 그 두 개와 연결된다(『정책기획 실습』 p.82·84)
- 보고서 제목 ↔ 장·절 소제목 ↔ 본문 내용이 같은 말을 한다

### 1.8 배포 게이트
- 출처가 달린 산출물은 요청이 없어도 배포 전에 출처 검증 도구(있다면)를 돌린다. 도구가 없으면 같은 기준으로 손으로 대조한다

## 2. 판단과 어조

### 2.1 판단은 단언한다
- 근거가 있으면 **단언**한다. `사료된다 · 판단된다 · 보인다 · 생각된다 · ~인 것 같다`로 흐리지 않는다. 저자 최종본 연구보고서에서 `~로 보임`·`사료됨`은 0회, 정책연구보고서 632건 관례도 1만 자당 0.5회다
- 헤징은 근거가 정말 약한 곳에만, **무엇이 약한지**와 함께 쓴다
- 양비론·"신중한 접근이 필요"·"다각도의 검토"·"종합적으로 고려"로 결론을 피하지 않는다. 비교했으면 **"그래서 어느 것"** 으로 끝낸다
- 사실과 의견을 구분하되, **의견을 분명히 낸다**. 사실만 늘어놓은 보고서는 보고서가 아니다(『정책기획 실습』 p.48)
- 사실 서술에 필자의 형용사("극심한"·"쇄도")를 섞지 않는다

### 2.2 요구하는 문장만 누그러뜨린다
**판단과 요구를 구분한다.** 저자가 AI 원고를 고칠 때 `~할 것` → `~하면 좋을 것으로 판단함`, `부족함` → `부족할 수 있음`으로 바꾼 것은 **상대(발주처·연구진)에게 무엇을 해 달라는 문장**에서만이었다. 보고서의 판단 문장은 그대로 단정이었다.
- 판단(무엇이 맞고 틀린가) → 단언
- 요구(상대가 무엇을 하라) → 제안형. 상세는 `30-advisory-opinion.md` §3
- 공문서 규범도 `~할 것`·`~바람`을 고압적 표현으로 보고 `~하기 바랍니다` 류로 바꾸게 한다(편람 p.55·76, 길잡이 p.22~23)

### 2.3 부풀리지 않는다
- **최상급·전칭은 비교 범위를 밝힌다**: "한국이 유일하다" → "본 장이 비교한 다섯 문서 가운데 … 한국뿐이다", "완전히 동일" → "같은 구조"
- 제안 중인 것을 확정·완성처럼 쓰지 않는다 — "아직 제안임, 설계안대로 확정할지는 모를 일"(저자 피드백)
- 추세를 부풀리지 않는다 — "수요가 커지는 게 아니라 이전에 있던 수요들이 구체화되는 추세"(저자 피드백)
- 대단치 않은 발견을 핵심 결과로 포장하지 않는다
- 기대효과는 조건과 함께: "~할 것으로 기대됨" 대신 "A가 전제될 경우 …까지 단축(○○ 사례 기준)"
- 모르는 것은 모른다고 쓴다. 모든 문장이 같은 확신이면 전체가 의심받는다

## 3. 개조식과 위계

### 3.1 문체는 문서 성격이 정한다
| 문서 | 문체 | 근거 |
|---|---|---|
| 정책·기획 연구보고서, 브리프, 추진계획(안), 자문의견서 | **개조식 `~함 / ~임 / ~음 / 명사형`** | 10개 세션에서 지시("모두 개조식으로 작성 ~함/~임 형태로"), 저자 최종본 `~다` 0% |
| 학술 성격의 연구서 장·자체 발간 연구서 | `~다` 서술 | 연구서 장 E 최종본 `~다` 43% |
| 학술논문 | `~다` 서술(별도 논문 문체 규칙) | 저자 논문 문체 규칙 |
| 심사 답변서 · 이메일 · 대중용 안내서 | `~입니다` 정중체 | "개조식 말고 ~입니다 형태로 답변서" · "전면 다 ~임 이런 식으로는 하지 말자"(저자 피드백) |

- 명사형 종결을 "일본어 투라 금지"라고 할 공식 근거는 없다(국립국어원 온라인가나다). 개조식 안에서는 쓰고, 서술형 본문에서는 쓰지 않는다

### 3.2 위계 기호
- 기본 `□ → ○ → - → · → *`. **발주처 양식이 `ㅇ`이면 `ㅇ`**을 따른다
- 법령의 원칙 항목 순서는 `1. → 가. → 1) → 가) → (1) → (가) → ① → ㉮`이고, "필요한 경우" `□ ○ - ㆍ` 같은 특수기호를 쓸 수 있다(시행규칙 제2조①). 보고서의 □○ 체계는 이 단서 조항에 기댄 관행이다
- `□ ○ - ·`는 법령상 순서가 정해진 체계가 아니라 쓸 수 있는 기호일 뿐이다(시행규칙 제2조). 그래서 **한 문서 안의 일관성**이 규칙이다
- **두 글머리 체계를 한 문서에 섞지 않는다**(보고서 양식 `●→―`와 브리프 양식 `□→○→-`를 섞는 것이 가장 흔한 사고)
- **부호 역할을 문서 전체에서 고정**한다. `※` = 참고·단서, `*` = 주석·각주. `※`에 주장·근거를 넣지 않는다
- 항목이 하나뿐이면 항목 기호를 붙이지 않는다(편람 p.61). 둘째 항목부터는 바로 위 항목보다 오른쪽으로 2타 들여 쓴다(편람 p.60)
- 글머리는 **문자 그대로** 쓴다. 마크다운 `-` `*`로 쓰면 한글 변환에서 부호가 사라진다
- `(라벨)` 줄: `□ (라벨) 요지` 형식을 쓴다. 라벨은 그 줄의 주제어다
- 판정 기호 `✗ · ○`는 쓰지 않고 문장으로 푼다(글머리 `○`와 다르다)

### 3.3 한 줄의 규율
- **한 줄에 한 초점, 한 구절.** "~다 — ~다"처럼 **두 문장을 대시로 이어 한 줄에 넣지 않는다** — "이런 건 지금 두 문장이잖아"(저자 피드백). 단 짧은 헤드라인 뒤 설명 대시("첫째, 통합성임 — 선행연구가 분리해 다루던 질문들을 연결함")는 저자 최종본에도 있어 허용
- **개조식이어도 꼭지마다 설명은 충분해야** 한다 — "개조식이지만 각 꼭지마다 설명이 충분해야 돼. 지금은 너무 짧아서 이해하기 어려움"(저자 피드백). 키워드만 있는 줄은 합쳐 문장으로 만든다
- 개조식 문장은 `~함 / ~임`으로 **닫는다**. 종결을 빼먹거나("…프로토콜을 확정") 쉼표로 동사를 생략하지("위치를 추적, 구성요소") 않는다
- 주어가 없는 문장에는 주어를 보충한다("해외 유사사업은 공통적으로…")
- **한 문장에 정보 하나.** "한 문장에 2개 이상의 정보를 담고 있으면 의미 파악이 어려워진다"(길잡이 p.92). 공문서는 "문장은 가급적 짧게 끊어서 항목별로 표현"한다(편람 p.75). 단 저자는 개조식 한 줄에 진단과 처방을 연결어미로 이어 쓰기도 한다(`30-advisory-opinion.md` §4.2) — 정보가 인과로 묶인 한 덩어리일 때만 잇는다
- **명사형 종결도 호응을 맞춘다**: "…높은 수준을 유지 중임" → "…유지하고 있음"(길잡이 p.90). `○` 머리와 그 아래 `-` 줄도 한 문장으로 읽히므로 호응을 맞춘다(p.90~91)
- 인과면 `-며`가 아니라 `-므로`로 잇는다(길잡이 p.93)
- 문단은 한 주제, 주제문을 먼저 쓴다. 한 문단은 5~8문장이 적당하다(길잡이 p.45·92)

### 3.4 두괄식
- 문서·장·절·블록은 **결론부터**. "먼저 결론을 내린 후 이유를 설명하는 것이 좋다"(편람 p.75), 맨 앞 문단은 본문 요약이나 결론을 담는다(길잡이 p.47). 첫 줄(첫 문단)만 읽혀 보고 "무엇이 문제이고 무엇을 하자는가"를 답하지 못하면 다시 쓴다(HKS 정책 메모 가이드)
- 흐름은 **배경 → 문제 제기 → 그래서 무엇을 하려는가**(저자 피드백)
- 결론은 판단(권고·선택·다음 행동)이다. "결론적으로" + 요약 재탕으로 끝내지 않는다

## 4. 낱말과 문장

### 4.1 쉽게 쓴다
- **"어렵고 그럴듯한" 글 금지** — 심사자·정책결정자가 한 번에 이해하는 말로. "AI가 쓴 것같이 내용이 어렵고… 그럴듯하게만 작성"(저자 피드백) 등 6개 세션
- 전문용어·직역 라벨 대신 **동작을 서술하는 평이한 말**. 처음 나오는 용어는 풀어 준다
- 짧은 말로 되면 긴 말을 쓰지 않는다. 뺄 수 있는 말은 뺀다
- **명사를 나열하지 않는다.** "과도한 명사화 구성을 피한다"(편람 p.45), "명사를 나열하는 식으로 문장을 작성하지 않는다"(길잡이 p.49). 조사·서술어를 살려 푼다
- 추상어보다 구체어: "추상적이고 일반적인 용어보다는 구체적이고 개별적인" 말(편람 p.75)
- 한자어·중복 표현을 줄인다: `제고함`→`높임`, `득하여`→`받아`, `과반수 이상`→`과반수`, `제출 유무 여부`→`제출 여부`(길잡이 p.13~14)
- 공문서의 법정 원칙도 같다: "간결하고 명확하게 표현하고 일반화되지 않은 약어와 전문용어 등의 사용을 피하여"(「행정업무의 운영 및 혁신에 관한 규정」 제7조②)
- 같은 말·같은 논리를 두 번 쓰지 않는다 — "논리가 두 번 들어가지 않게". 배경과 현황이 같은 통계를 되풀이하지 않는다
- 청중의 전문성에 맞춘다. 국장·법률가 앞에서 **비전문가 티**가 나지 않게(저자 피드백)

### 4.2 번역투를 쓰지 않는다
- "정박 — 이런 표현 지양. 번역투잖아, 다음부터 쭉"(저자 피드백) 등 5개 세션
- 저자가 지목한 직역어: `정박` · `원산지` · `문법`(비유) · `기른 사람` · `고용량 생산`(→대량생산) · `발화` · `준산업적 규모(near-industrial scale)`(→준산업 규모)
- 어문 규범형: `~에 있어서` · `~하는 것이 가능하다` · `~에 의해 ~되다` · `~의` 연쇄 · `~적` 남용 · 이중피동(`되어지다`·`보여지다`)
- 영문 병기는 **첫 등장 1회, 필요할 때만**. 한국어 개념명에 영문 번역을 괄호로 덧붙이지 않는다: "'○○ 사회(○○ Society)'" → "'○○ 사회'"

### 4.3 저자가 교체를 요구한 낱말
지목되면 **대체어를 여러 개 제시하고 문서 전체에서** 바꾼다. 지금까지 지목된 것(8개 세션):

| 쓰지 않는다 | 이유 |
|---|---|
| 압박한다 · 기계(비유) · 종언 · 기능 정지 | 과장된 비유 |
| 시간축 불일치 · 이행요건 미충족 | 직역 조어 |
| 논리적이고 설득력 있는 | 자기 평가 |
| 박차를 가하다 · ~의 전유물 | 상투 수사 |
| 다양한 · 체계적 · 종합적 · 효과적 · 혁신적 | 빈 수식어 — 대상·단계·기준·수치로 바꾼다 |
| 급변하는 · ○○ 시대를 맞아 · 오늘날 | 시대 담론 서두 — 구체 계기(사건·수치·지시)로 연다 |
| 연구에 따르면 · 전문가들은 · ~로 알려져 있다 | 무출처 통설 — 실명 출처를 못 달면 문장 삭제 |

### 4.4 AI티 신호
- 최종 검토 단계에서 **AI가 쓴 티가 나는 문장을 걷어 낸다**(7개 세션). 진단은 AI 문체 진단 도구(있다면)로 한다
- **긴 대시(—) 꼬리 해설**이 저자 문서와 AI 초안을 가르는 가장 뚜렷한 표지다. 저자 최종본 1만 자당 0.9~5.1회(참고문헌 줄 제외), AI 초안 11.5~50회. 정책연구보고서 C에서 저자가 208개를 57개로 줄였다(참고문헌 제외 밀도 14.4→5.1). **대시 뒤에 해설을 덧붙이지 말고 문장을 끊거나 지운다.** `(라벨) — 부제` 형식의 라벨 대시는 허용
- **"이는 ~를 반영함"·"이는 ~를 의미함" 꼬리**를 붙이지 않는다. 해석이 새 정보이면 `(시사점)` 줄로 독립시킨다. "이는 ~을 시사함" 형태의 해석 줄은 저자 최종본에도 남아 있어 허용
- **개수 수사 금지**: "여덟 함정 · 아홉 실천 · 세 갈래 · N종"처럼 수사로 쓴 개수는 뺀다 — "숫자로 몇 개인지 굳이 넣은 표현은 빼자. 불필요하잖아"(저자 피드백). 단 **구조를 예고하는 개수**("네 가지 정책 요구와 본 연구의 대응" — 저자 최종본에 유지), **공식 명칭이 된 수량**("13대 과제" — 저자가 "13개 과제"에서 직접 고침), ①②③ 열거는 쓴다
- **"단순히 X가 아니라 Y" · "X에 그치지 않고 Y"** 대비 구문은 문서당 1~2회까지(제안서 차별성 논증은 제안서 규칙을 따른다)
- 세 낱말 가운뎃점 압축 조어("오정의·오배치·역방향")를 풀어 쓴다
- 챗봇 관습(이모지·"살펴보겠습니다"·"다음은 ~입니다"·수평선) 금지
- **본문 볼드 남발 금지** — 제목·소제목과 양식이 정한 자리만("볼드체가 너무 많아서 가독성 떨어짐"). 문장 전체를 볼드로 감싸지 않는다

## 6. 표와 그림

- **표는 비교·수치, 과정·절차는 삽도**로 — "절차(과정) 순서를 표 말고 삽도로"(7개 세션)
- 표는 보조 자료다. 표가 보고서를 채우고 글이 없거나, 분석을 글 대신 표로 붙이지 않는다. 표 다음에는 **그래서 무엇인지** 한두 줄을 쓴다
- 같은 내용을 표와 그림으로 중복하지 않는다
- 모든 표·그림에 **출처줄**을 달고(`* 출처:`/`자료:`), 본문에서 번호로 부르고 해석한다
- 삽도 프롬프트는 디자인이 아니라 **내용·구성 설명**으로 쓴다 — "디자인 말고 내용 중심으로"
- 막대그래프 축을 끊지 않는다, 3D 금지, 수치는 오른쪽 정렬·천 단위 쉼표(영국 정부 분석직 지침)
- 캡션 위치·부호는 유형 파일과 양식을 따른다

## 7. 편집·양식·전달

### 7.1 원본을 깨지 않는다
- **원본 편집(양식·서식)을 절대 깨지 않는다. 재생성하지 말고 그 파일에 제자리 수정**한다 — "편집 건드리지 말고 그 위에 수정만 하면 되는데 왜 다 편집 바꾼 거야"(10개 세션). 원본 서식을 보존하는 제자리 수정 도구가 있으면 그것을 쓴다
- 현재 편집 양식을 준수하고 서식·구조를 임의로 바꾸지 않는다(표 문단 스타일 포함)
- 기본 산출 형식은 **hwpx**. 짧은 회의자료가 한글에서 깨지면 html 허용. 복사용 표는 html 표 병행
- 저자가 손본 앞부분은 **문체·서식 기준본**으로 삼아 나머지를 맞춘다. 저자가 점검을 끝낸 구간은 건드리지 않는다

### 7.2 수정 표시의 색
| 색 | 의미 | 근거 |
|---|---|---|
| **파랑** | 이번에 고친 곳 · 확인이 필요한 곳 | 20회 이상 반복 지시 |
| **빨강** | 향후 보완·2차 전문가 검토 뒤 반영할 것만 | 저자 지시 |
| **핑크** | 저자가 직접 추가·수정한 부분 | 기획보고서 G 개정본 |
- 산출은 **검토본(색 표시) + 최종본(무표시) + 교정내역 md** 3종. 저자는 수정안을 한 건씩 취사선택한다
- 메모(주석)로 단 지시는 **읽고 반영한 뒤 메모를 삭제**한다

### 7.3 작업 흔적을 지운다
배포 전 **전수 검색**으로 지운다.
- 웹조사 잔재: `?utm_source=chatgpt.com`, 마크다운 링크 문법, 링크 앵커 텍스트
- 편집 메모: "피드백 주신 내용을 반영하여", "이번 보완에서는", "이 그림도 좀 더 논의"
- 미검증 표지: `⟪…⟫`, `〔검증〕`, 파란색 안내문, `〔책임자 표시본〕`
- 내부 파일명·폴더명·버전명: `03_research_boost`, `_강화본`
- 괄호 안 장·절 상호참조: "(제2장 제1절에서 상술함)" — **괄호에는 인용만** 넣는다. 표·그림 번호 참조 `(그림 Ⅶ-1)`과 줄 머리 라벨 `□ (효과성, 제4장)`은 허용

### 7.4 저자와 일하는 방식
- **"답변창에 답변 줘"면 파일을 건드리지 않는다**(7개 세션)
- **핵심 문안(제목·과업명·목적 문장)은 후보를 여러 개** 주고 저자가 고른다 — "여러 개로 제안해줘 봐. 내가 보고 고를게"(6개 세션)
- 목차·구성은 **승인 후** 집필한다
- 숫자 표는 표로 먼저 보여 주고 승인 뒤 엑셀·hwpx에 반영한다
- 초안은 넉넉히 넣고 삭제는 저자가 한다 — "일단 다 넣어 봐, 내가 뺄 건 빼고". 삭제를 지시받으면 **국소적으로** 뺀다("너무 다 뺐어, 원래대로 돌리고 불필요한 부분만")
- "보강 필요"로 비워 두지 말고 직접 채워 제안한다
- 같은 지적이 두 번 나오면 이 규칙 파일이나 점검 스크립트에 박는다

## 8. 좋은 보고서의 기준 (외부 표준에서 수렴한 것)

길잡이의 보고서 점검 항목도 같은 방향이다: 보고서는 "하나의 텍스트로서 내용이 완결되어야" 하고, 유사한 사실을 나열하지 말고 짜임새 있게 구성하며, 결론에 대안·기대효과·향후 조치를 담는다(길잡이 p.55·80·82).

세 곳 이상의 독립 출처가 같은 말을 하는 원칙이다. 위 규칙과 겹치는 것은 한 줄로만 적는다.

| 원칙 | 이 파일에서 |
|---|---|
| 결론·요점을 맨 앞에(두괄식·BLUF·피라미드) | §3.4 |
| 독자(의사결정권자) 중심 — 독자가 아는 것·궁금한 것·제약에 맞춘다. 독자가 이미 아는 배경은 줄인다 | §4.1 |
| 짧은 말, 뺄 수 있는 말은 뺀다 | §4.1 |
| 주체를 밝힌다(무주어 당위 금지) | §3.3, `10-research-report.md` §2.3 |
| 전문용어는 풀이 | §4.1 |
| 사실과 의견을 구분하되 의견을 분명히 | §2.1 |
| 권고는 근거가 뒷받침하는 만큼만 | §2 |
| 제목 ↔ 소제목 ↔ 문제 ↔ 대안 ↔ 추진계획의 정합 | §1.7 |
| 구체·정량, 문제를 수량화("과밀"은 이슈일 뿐, 수량화하고 구체화해야 정책 문제가 된다 — HKS 원문) | §1.2 |
| 요약은 단독으로 읽힌다 | `20-brief.md` §4 |
| 대안을 복수로 놓고 기준으로 비교한 뒤 권고 | `10-research-report.md` §2.3 |
| 실행 정보: 시기·담당·자원·다음 단계 | `10-research-report.md` §2.3, `20-brief.md` §3 |
| 표·그림은 목적이 있을 때만, 글을 대신하지 않는다 | §6 |
| 정확성이 신뢰의 전제 — 오탈자도 신뢰를 깎는다 | §1, §5 |
| **가정과 한계를 드러낸다** — 핵심 판단이 기대는 가정을 밝히고, 그 가정이 틀리면 무엇이 무너지는지 한 줄. 권고는 발견에서 논리적으로 따라 나와야 한다 | 신규(RAND 2022 기준 원문: Transparency — "assumptions … limitations" 문서화, Rigor — "recommendations follow logically from these findings") |

### 나쁜 보고서의 신호
- 결론이 늦게 나온다 · 읽는 사람이 원하는 내용을 보물찾기하듯 뒤져야 한다
- 개선방안 자리에 **절차만** 있다("TF 구성", "의견수렴", "검토") — 절차는 방안이 아니다
- 현황·문제점에서 제기한 것이 대안에서 사라진다
- 일정·기한·담당이 없는 추진계획
- 해외 사례를 한국 여건 점검 없이 가져온다
- "대충 뜻이 통할 것 같다"는 태도(『정책기획 실습』 p.48)

## 9. 배포 전 공통 점검표

기계 점검 항목은 `scripts/rcheck.py check <파일> --type common`로 먼저 돌린다.

- [ ] 첫 줄(첫 문단)만 읽어도 무엇이 문제이고 무엇을 하자는지 보인다
- [ ] 모든 수치에 출처·기준연도가 있고, 추정 수치는 합산식이 있으며, 파생 수치까지 검산했다
- [ ] 내부 작업자료(RFP·회의록·메일·메모)를 출처로 달지 않았다
- [ ] 직접인용은 원문과 문자 그대로 일치한다
- [ ] 부처명·제도·법령·계획 차수가 현행이다
- [ ] 판단 문장에 `사료된다·보인다·판단된다`가 없고, 비교 절은 결론으로 끝난다
- [ ] 최상급·전칭("유일·완전히·모든")에 비교 범위가 붙었다
- [ ] 제안 중·계획 중인 것을 확정·완성으로 쓰지 않았다
- [ ] 문체가 문서 성격과 맞고(§3.1), 글머리 체계가 하나다
- [ ] 한 줄에 두 문장을 대시로 잇지 않았고, 키워드만 있는 줄이 없다
- [ ] 긴 대시 꼬리 해설·"이는 ~를 반영함"·개수 수사·번역투·지목된 낱말이 없다
- [ ] 「」는 법령·문서명에만, 개념은 ' '
- [ ] 요약문·본문·표·부록의 용어·수치가 일치한다
- [ ] 작업 흔적(utm·편집 메모·미검증 표지·내부 파일명·괄호 상호참조)을 전수 검색해 지웠다
- [ ] 원본 양식을 깨지 않았고, 수정 색 규율(파랑·빨강·핑크)을 지켰다
- [ ] 띄어쓰기를 전수 검사했다
- [ ] 출처 검증을 돌렸다(출처가 달린 경우)
